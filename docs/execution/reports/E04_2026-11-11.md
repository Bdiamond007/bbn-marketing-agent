# Rapport E04 — Base, migrations et isolation

- Statut : **VERIFIED_LOCAL** — gate d'isolation franchi localement
- Commit : 2304bc7
- Environnement : PostgreSQL 16.15 (binaires locaux, `pnpm pg:local`), base de test jetable `bbn_test` recréée à chaque exécution

## Livré

- `packages/db/migrations/0001_init.sql` : 33 tables (modèle §10 complet), FK composites `(organization_id, id)`, index exigés (publication état/next_attempt et organisation/date, audit organisation/date), unicités (variante sujet/réseau/langue, numéro de révision), contrainte d'exclusion des cycles `[start,end)`.
- Rôles `bbn_migrator` (propriétaire) / `bbn_app` (runtime, sans BYPASSRLS, sans objet, ne peut pas endosser le propriétaire) — `packages/db/bootstrap/`.
- RLS activée **et forcée** sur toutes les tables ; `webhook_events` sans politique (aucun accès runtime).
- Contexte transactionnel `withTenant` / `withUser` (`set_config(..., true)`), vérification de membership dans la transaction, refus indistinct.
- Invariants en base : dernier propriétaire (contrainte différée, transfert atomique possible), révisions et guidelines immuables (même pour le propriétaire), ledger/audit sans UPDATE/DELETE pour le runtime, approbation liée à l'empreinte et à la destination (réseau + marque), approbation invalidée non réactivable, révision courante de la même variante, notification limitée aux membres, invitation ≤ 7 jours, accès support ≤ 72 h et motivé, statistique indisponible = NULL, `published` exige un type de confirmation.
- Seed **fictif** A/B (`pnpm db:seed`, idempotent), écrit via `bbn_app` sous RLS.
- Schéma Drizzle généré par introspection et post-traité (ADR-0004).

## Tests SQL réels (extraits)

Contexte absent ⇒ 0 ligne sur 6 tables et INSERT refusé (42501) ; contexte qui ne survit pas à la transaction sur une connexion poolée (pool de taille 1) ; contexte invalide refusé ; utilisateur non membre refusé ; A ne lit aucun objet de B même par identifiant ; UPDATE/DELETE de B par A ⇒ 0 ligne ; INSERT étiqueté B depuis A refusé (WITH CHECK) ; déplacement vers B refusé ; 4 FK inter-tenant refusées (23503) ; rôle runtime sans superuser/BYPASSRLS/objets ; aucune table sans RLS forcée ; invariants listés ci-dessus.

**Test de mutation** : politique `tenant_isolation` remplacée par `USING (true)` ⇒ 5 tests échouent (contexte absent, pooling, lecture B par A, écriture B par A, contenu du seed). Migration restaurée à l'identique (somme SHA-256 vérifiée).

## Défauts trouvés et corrigés

- Le rôle de migration ne pouvait pas écrire les plans (RLS forcée sans politique d'écriture) : politique `plans_reference_write` ajoutée à 0001 **avant toute publication** (ADR-0004).
- `drizzle-kit pull` réordonne mal les colonnes des FK composites : FK/politiques/checks retirés du schéma généré (risque R11).
