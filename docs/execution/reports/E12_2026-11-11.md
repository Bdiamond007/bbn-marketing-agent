## Validation (critères E12)

| Critère | Preuve |
|---|---|
| Atomicité | Transaction métier annulée ⇒ aucun événement ; validée ⇒ un événement ; clé de déduplication respectée |
| Crash avant envoi | Événement réclamé puis abandonné : non repris tant que le bail est valide, puis repris après expiration et traité une fois |
| Crash après envoi, avant marquage | Pire cas (file sans déduplication) : message présent deux fois, un doublon ignoré, une seule réservation de quota |
| Livraison multiple | 5 doublons forcés par la file ⇒ une seule réservation |
| Bail expiré | Le relais retardataire ne peut plus marquer (`false`), le relais repreneur oui ; deux relais concurrents réclament des lots disjoints |
| Pas de perte ni de double débit | L'effet est volontairement non idempotent (nouvelle réservation à chaque exécution) : seule l'inbox empêche le double débit |
| Test de mutation | Sans l'inbox : 2 tests échouent (crash après envoi, livraison multiple) |
| DLQ et échecs | Envoi en échec ⇒ nouvelle tentative différée puis « mort » ; handler en échec ⇒ DLQ, sans effet partiel (transaction annulée) |
| Corrélation | Le `correlationId` de l'événement se retrouve dans l'enveloppe consommée |

## Défaut trouvé et corrigé

Le binaire construit du worker (`dist/main.js`) ne démarrait plus depuis E07.

- **Cause** : `pg`, `drizzle-orm` et `sharp` étaient externes au bundle sans être déclarés dans `apps/worker/package.json`.
- **Pourquoi les tests ne l'ont pas vu** : unitaires, base et E2E n'exécutent pas le binaire du worker.
- **Correction** : dépendances déclarées, et test de fumée du binaire ajouté à la CI et à la vérification sur clone neuf.
